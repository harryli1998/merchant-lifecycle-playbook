# 从广告主生命周期到客户运营决策体系

状态：公开参考实现的方法说明。原项目依据 Harry 的项目复盘笔记；公开实现使用合成数据，不能用于验证历史业务结果。

## 解决的问题

当团队用相似方式对待新客户、成长客户、稳定客户和正在减少使用的客户时，有限的运营资源很难分配。这个框架将行为数据转化为可解释的客户状态、行动名单和效果验证流程。

## 原项目的可复用经验

原项目采用入驻时间、广告消耗、消耗趋势和投放天数，区分引入、成长、成熟和流失风险四个阶段。按品类与竞争强度调整阈值，通过六个月历史回测、阶段迁移矩阵、样本审核和运营反馈迭代规则，并让不同阶段对应不同运营策略。

内部复盘记载上线后收入增长约 3%。这属于历史观察结果，不是本仓库复现结果，也不是经过随机实验识别的因果收益。此数字不作为公开演示的收益承诺。

## 六步方法

1. **定义决策。** 明确由谁在什么频率决定触达谁、采取什么动作，以及每周可处理的客户数量。先确定业务目标和成本约束。
2. **建立数据契约。** 确认客户实体、起始日期、行为事件、价值指标、业务分组和完整数据覆盖期。区分真实零活动与数据缺失，明确金额口径及退款处理。
3. **构建可解释状态。** 使用客户年龄、最近窗口价值、相对前一窗口的变化和活动频率。阈值按业务分组校准，规则版本化，记录命中原因。
4. **验证状态是否有用。** 逐期重建历史快照，仅使用当时可见数据；检查分层覆盖率、迁移、标签波动和样本解释。单独保留未来观察期，验证风险与后续行为的关系。
5. **转化为行动。** 为每类状态指定负责人、诊断步骤、动作、执行周期、成本和停止条件。在容量限制下进一步按价值和风险排序。
6. **衡量并迭代。** 分开评估标签质量、团队执行率和业务增量；条件允许时在阶段内随机分配干预与保留组，记录收入、贡献利润、留存与负面影响。

## 跨行业映射

| 维度 | 广告主 | 电商消费者 | B2B / SaaS |
|---|---|---|---|
| 分析实体 | 广告账户 / 商户 | 客户 | 企业账户 |
| 年龄起点 | 开户 / 首投 | 注册 / 首购 | 签约 / 激活 |
| 价值 | 广告消耗 | 净收入 / 贡献利润 | 经常性收入 |
| 活动 | 投放天数 | 购买次数 / 购买天数 | 核心功能使用天数 |
| 风险信号 | 消耗与投放下降 | 超出预期复购周期 | 核心使用下降 / 临近续费 |
| 校准分组 | 品类、竞争强度 | 品类、购买周期 | 套餐、客户规模、合同周期 |

迁移时保留决策流程，重新定义行为和阈值。不能把广告的 30 天窗口与下降 50% 阈值直接用于低频购买或年度订阅。

## 公开实现必须补足的边界

- 原笔记的规则是示例，存在重叠和未覆盖情况。实现需明确优先级，保留“待观察 / 未分类”，不强行把所有客户归入四阶段。
- 前期价值为零时，增长率不可直接计算；区分首次激活、重新激活和持续不活跃。
- 新客户缺少完整前期窗口，不应因为没有历史消费而被判断为流失。
- 流失风险不等于已经流失；标签改变也不等于客户被成功挽回。
- 迁移矩阵只比较相邻快照中可观察的同一批实体；新增、退出及缺失覆盖单列报告。
- 阈值校准不得偷看未来；季节性、促销与业务结构变化需单独解释。
- 成熟度与客户价值是两个维度；稳定的小客户不应自动被判定为不健康。

## v2：把方法变成可供客户讨论的案例

本版聚焦“首次投放后是否持续使用”，使用 480 个虚构账户、360 天完整日粒度记录。案例中的渠道结构变化和停投前行为由生成器设定，不能作为真实业务规律。

- **先诊断 cohort：** 以首个正消费日为第 0 天，观察第 30–59 天是否再次消费。只有完整观察到第 59 天的账户才进入分母；观察不完整显示 N/A，不当作流失。入驻前已有消费历史的存量账户不进入首投 cohort。
- **把阶段与价值拆开：** 稳定的小商户仍然可以是 Stable；当前消费为零单列 Inactive；风险标签与已经不活跃分开。
- **验证误报和漏报：** 在同一批具备完整前期且当前仍消费的账户窗口上，对照“仅消费下降”与“消费下降且低活跃”规则。展示精确率、召回率、分母、基础发生率及阈值变化后的名单重合率。相同账户重复出现，不作独立样本显著性推断。
- **把运营容量显式化：** 每周 0–50 家可调；激活优先，再处理仍消费的风险商户，各组按历史参考消费排序。这个排序是运营政策，不是预测干预 ROI。页面同时展示未入选名单并导出入选账户。
- **把未知保留下来：** 商户停止投放可能因为活动结束、季节性、广告效率或服务问题。现有字段不能判断原因，行动建议应先诊断，再决定是否提供激励。
